> 更新于 2026-10-27。作者确认调整方向：核心是“获取游戏状态 → 综合上下文 → 发表评论”；节省 token、缩短延迟，应在验证主流程之后进行。
> 后续提出扩展到日常工作与娱乐，并要求以 OpenClaw skill 开启最小 demo，定时看屏、适时通过 mac 通知评论。主流程推广为“获取当前活动状态 → 综合上下文 → 发表评论”。macOS demo 已实现；此前 v1–v4 讨论保留在 [设计历史](DESIGN_HISTORY.md)，当前方案以本文件为准。
> 2026-10-28：已从无工具的单次推理升级为 `main` agent 的固定普通陪伴会话，共享启动上下文与 brain 读写；当前接入方式见第7节。
> 同日接入 macOS 自带 `say`：最终通知评论默认同步播报，中文音色 Tingting，原有沉默与限频规则同时控制通知和语音。

## 1. 要验证的体验

一个坐在旁边陪你工作、娱乐或打游戏的桌面伙伴，能理解屏幕上正在发生的事，记得刚才的经历，结合你们的对话和它的性格，偶尔评论、吐槽或接话。

核心问题：它能否说出你愿意听、愿意接的话，让你感觉它跟你共同经历了眼前的事情？

## 2. 目标与边界

- 通用：覆盖屏幕内的日常工作、娱乐和游戏；初版不宣称已能可靠理解所有活动。
- 随开随用、零针对性配置：不填 ROI、不选游戏类型、不装游戏插件、不逐个维护游戏或应用适配。
- 有记忆、人格和注入的上下文。
- 长期支持语音输入、输出与打断；初版先用文字验证评论质量。
- 初版不做本地 OCR。

自动获取游戏名等上下文可以作为候选，不需要用户配置；是否纳入初版仍待实现时决定。

## 3. 最小主流程

```text
定时获取屏幕画面，保留最近几帧及时间信息
                     ↓
结合近期活动、对话、记忆和人格
                     ↓
模型理解状态，决定发表评论或保持沉默
                     ↓
显示文字评论，记录用户回应与实际运行数据
```

### 获取当前活动状态

先用定时截图直接提供视觉信息。具体频率通过初版试玩确定，不要求先实现事件检测或学习“什么时候看”。保留最近几帧，帮助区分当前画面与刚才发生的变化；看不清或无法确认的内容应保留不确定性。

### 综合上下文

上下文包括近期可确认的活动、用户说过的话、它之前的评论、相关记忆和人格。需要能接上前情，避免每张图都像第一次看到，也避免反复评论同一件事。

近期图像采用有限窗口；陪伴对话历史由 OpenClaw 会话管理。长期记忆沿用同一工作区的 brain 架构，通过现有文件工具和协议按需读写，不另建记忆平台。

### 发表评论

结合当前状态和上下文，决定说什么或保持沉默。评论质量、重复和打扰程度都属于主流程验证；具体语气与开口倾向由用户在试玩中调整。

这三步是逻辑职责，不要求拆成视觉子会话、共享状态槽和人格决策三段。当前由一次完整 agent 轮次完成，必要时可在该轮调用记忆或 image 工具，因而不再保证只有一次底层模型请求。

## 4. 第一轮怎么验证

1. 跑通截图、上下文输入到文字评论的闭环。
2. 进行一次约半小时的真实陪伴试玩，可以先选游戏，也可用实际工作或娱乐活动；通过 OpenClaw 对话回应并更新交接。
3. 记录有代表性的评论、对应画面与前情，以及用户的实际反馈。
4. 优先修正看错、接不上前情、重复、空泛和打扰问题，再试玩。

每轮重点判断：

| 维度 | 问题 |
|---|---|
| 状态理解 | 是否看错事件，把猜测说成事实？ |
| 上下文连续性 | 是否记得前情，能接住用户的话？ |
| 评论质量 | 是否具体、有趣，符合这个伙伴的性格？ |
| 打扰程度 | 是否重复、插话扫兴，用户是否想让它闭嘴？ |
| 陪伴意愿 | 用户是否愿意接话，下一次还想打开？ |

由真实试玩和用户反馈判断体验。模型自评可以辅助整理，不能替代这些判断；这轮不需要先录 5–10 局、冻结评测集或训练注意力策略。

## 5. 测量与后续优化

记录调用轮数、失败和时间戳。当前完整 agent 结果提供实际 token 用量，按原始字段记录，不把调用次数冒充费用实测。文字版记录从采屏开始到通知提交的耗时，区分采样等待与处理耗时；通知可见时间仍待用户观察。语音接入后另测从事件到首音的完整耗时。

现有 [分项测量](MEASUREMENTS.md) 仅作参考，不能当作主流程已验证或实际端到端表现。

主流程有价值后，根据真实瓶颈再选择优化：

- token 与带宽：调整图像尺寸、采样频率和上下文保留方式。
- 延迟：根据完整链路测量决定是否流式输出、并行或拆分调用。
- 本地占用：有需要时再比较持续采屏与按次截图。
- 注意力调度：外周感知、事件触发、LLM 生成策略与回放择优，均为待验证候选。

优化应与初版基线比较，检查省下的成本是否损害状态理解与陪伴体验。注意力学习是否需要做，目前没有结论。

## 6. 设计调整的原因

早先讨论从陪伴体验转向了采样成本，最终形成 v4：三个变化量、LLM 生成 `should_look`、回放评估、状态槽与人格层。它引入了尚未验证的前提：低维信号是否足够、策略能否泛化、模型自评是否符合用户偏好。

2026-10-27，作者明确确认先验证主流程。由此撤下“注意力策略必须自长”的初版硬约束，以及“先攒数据再写规则”的前置顺序。v4 保留作后续研究材料，不作为当前待办。

此前相关项目调研也保留在设计历史。它只能提供参考方向，尚不足以证明市场存在无人覆盖的空位。

## 7. 已实现的最小 demo

- 形式：OpenClaw `kibitz` skill + Python 标准库后台循环，通过官方 `openclaw agent` 调用固定的 `agent:main:kibitz` 普通会话。源码见 `skills/kibitz/`，无需修改 OpenClaw 源码或配置。
- 默认：目标每5秒一轮、主屏、最近两帧、完整 agent 轮次。请求串行，超时或停止会请求取消远端轮次，不积压截图。
- 输出：模型返回滚动前情摘要、屏幕是否实质变化、兴趣等级与评论（可为空），最终评论经 macOS 系统通知提交并同步用 say 读出；精确重复评论不重复投递，语义重复由模型判断。语音串行、不排队，stop 可中断；--no-speech 保留通知，--no-notify 同时关闭两路。
- 发言节奏（用户最新要求）：通常平均约每分钟一条，有趣事件可短时多说，变化小或兴趣低时沉默。程序每60秒恢复一条额度、最多存两条；普通评论至少间隔60秒，high 事件可用短时额度。首轮、screen_changed=false 或 low 不发送。向模型注入额度、最近60秒发言次数与上次发言时间；受限候选直接丢弃，不排队补发。兴趣与实质变化仍由视觉模型判断，频率预算由程序执行。
- 上下文：同一 main agent、同一 workspace 的正常完整启动注入，显式接续自定义 BOOTSTRAP 和 brain/README；保留独立持续会话与最近12条评论。偏好补充不再代替身份与背景。启动报告缺文件、工具、会话/工作区不匹配或出现嵌入式回退时视为失败。
- 共享记忆：按当前 brain 读取/写入协议直接使用文件工具；事实、事件、解释分层，编译产物走 memory-curator。主聊天尚未入库的新消息不自动复制，可通过 note 排队交给陪伴会话，成功处理后移出队列。
- 生命周期：start / status / stop / once / init；防重复启动，连续三轮失败退出，正常退出删除临时截图；不登录自启。停止不删除 OpenClaw 会话历史或已保存记忆。
- 边界：允许与陪伴相关的记忆工具读写，不执行屏幕内指令，不控制应用或键鼠，不代发消息，不读取/复制密钥，不修改 OpenClaw 运行时配置。
- 验证：本地行为检查以及真实完整注入、临时 brain 记录读写/编辑/清理、同一会话续接、随机颜色图片识别已通过；持续陪伴质量仍待真实使用评估。

## 8. 待试玩确认

- 默认模型、截图频率、近期帧数量和上下文窗口是否适合实际活动。
- 评论质量与开口倾向如何通过真实反馈调整。
- 当前默认采主屏；更细的窗口选取、截图范围和记录保留方式待后续决定。
- 语音链路及跨平台实现，待文字闭环验证后决定。
